# Module F — 기존 5단계 유지, 화면만 간소화

## 변경 경계

- 평면도 수동 경로는 도면 열기 → 찍기 → 손질 → 수리계산 → 수리계산 입력 변환의 **5단계 그대로**다. 미도달 단계의 원래 진입 가드도 유지한다.
- 자동 추출·계통도·기계실은 각자의 기존 단계 흐름을 유지한다. 최불리 후보 선정은 실제 실행 순서대로 손질 단계에 남긴다.
- 서버 API, 추출·물흐름·관경·피팅·수리계산·역산·SDF 작성 함수, 저장 데이터 형식은 이번 변경 대상이 아니다.
- `module_f_layout.js/css`가 기존 DOM 컨트롤을 복제하지 않고 이동한다. 원래 ID, 이벤트 처리기, 입력값과 기본값을 유지한다.
- H에서는 새 화면 정리 코드를 실행하지 않는다. H 전용 파일과 기존 F CSS도 변경하지 않았다.
- 공용 F 스크립트의 변경은 빈 화면의 5단계 표시, 입력표 속성 카드 접근, `null`/`undefined` 안내 개선, 변환 단계의 표 읽기 전용 처리다.

## 화면 구성

| 위치 | 기본 화면 | 접어서 제공하는 항목 |
| --- | --- | --- |
| 찍기 | 배관·헤드 선택, 펜 영역 지정, 다음 단계 | 헤드 프로필, 자동 추천·채택 결과, 재료 분류, 긴 도움말 |
| 손질 | 접속점, 이음·삭제, 물흐름, 손질 저장, 후보 선정 | 트리·루프·그리드 방식, 기준 헤드 수, 자동 이음, 배경·격자, 처리 상태 |
| 수리계산 | 표 확정, 배관 규격, 필요한 검토용 관경·표고, 평면/아이소 전환, 확인할 항목 | 투영·고도 표시, 신축배관, 헤드 채움, 상세 진단·수정 기록·표기 근거 |
| 입력 변환 | 파일 생성, SDF 다운로드, 선택된 출력 형식 요약 | 다른 형식의 출력, 상세 변환 옵션 |
| 통합 | 급수방식, 결합, SDF 생성·다운로드 | 관경·펌프 역산, 격자·원도면 겹침, 기타 형식 |

긴 안내는 삭제하지 않고 펼침 설명으로 남긴다. 오래된 표, 미확정 관경, 오류·필수 입력은 짧은 상태로 계속 드러낸다. 숨긴 출력 옵션이 체크돼 있으면 실제 선택 형식을 요약에 표시한다. 새 기본값을 임의로 적용하지 않는다.

## 넓은 입력표

- 수리계산/입력 변환 상단의 **입력표**에서 화면 폭 전체를 사용한다. **배관망**으로 기존 화면에 돌아간다.
- 번호·양 끝 노드·호칭경·길이·재질/규격·관경 근거 등 기본 열부터 보여 준다. 계산용 내부 열은 **상세 열 보기**로 접근한다.
- 숫자 오른쪽 정렬, 단위 표시, 줄바꿈 방지, 긴 목록의 열 제목 고정을 적용했다.
- 소수는 기본 화면에서만 최대 셋째 자리로 표시한다. 원래 정밀도는 상세 열 또는 숫자에 마우스를 올려 확인한다. 모델·계산·출력값은 반올림하지 않는다.
- 원래 행 선택 동작으로 속성·근거를 확인한다. 수리계산 단계에서는 기존 관경 편집/되돌리기를 사용한다. 변환 단계는 읽기 전용이며 수정은 04 수리계산에서 한다.
- 단계나 도면 슬롯을 바꾸면 표 보기를 닫아 다른 도면의 표로 오해하지 않게 한다.
- 새 도구줄은 캔버스 밖에 둔다. 기존 캔버스·클릭 판정·부속 표시·XYZ 편집 핸들은 동일한 좌표 영역을 유지한다.

## 검증

실제 UI와 계산 엔진을 사용하되, 별도 브라우저/임시 HTTP 서버/합성 배관망에서 수행한다. 사용자 작업 세션은 재사용하거나 수정하지 않는다.

- 새 레이아웃 시험: 원래 컨트롤 ID·노드·이벤트·설정값 보존, 5단계 가드, 고급 설정 열고 닫을 때 데이터와 API 변경 없음.
- 5종 표 선택, 넓은 표·상세 열·200행 스크롤·정밀도 보존, 행 선택·속성 카드, 상태 안내 및 비활성 가드.
- 실제 관경 수정·되돌리기, 통합 SDF 생성·XML 파싱·다운로드.
- 기존 카메라·선택·피팅 표시·XYZ 편집·통합 원도면 표시·펜 영역·계통도·연속관·관경 근거·역산 시험.
- H 라우트와 브라우저 회귀, SDF 축약 및 루프 검토 출력 회귀.
- 1500px 및 1100px 폭에서 화면 확인. 예시 캡처: `data/module_f_ui_20260928/`.

현장 DXF 전체 재추출 및 PIPENET 프로그램 내부 재계산은 이 프론트엔드 변경의 검증 범위가 아니다. 기존 실제 DXF 시험은 별도 opt-in 조건을 유지한다.

최종 결과: 관련 시험 **150개 통과, 실제 DXF opt-in 시험 1개 건너뜀**. 기존 브라우저 시험에서 이동한 컨트롤은 고급 설정/안내를 먼저 펼쳐 접근하도록 갱신했다. 도면 클릭·피팅 선택·캔버스 좌표 시험의 기존 판정 기준은 유지했다. JavaScript 구문 검사도 통과했다.

## 배포

사용자의 손질 저장·재시작 승인을 받은 후 5051에 반영한다. 5052는 건드리지 않는다. 반영 후 강력 새로고침하고 저장한 도면을 다시 열면 된다. 이번 화면 정리만을 위해 계산값을 다시 생성할 필요는 없다.

2026-09-28 15:08 KST에 5051 가동 완료(PID 12044, HTTP 200). 5052는 PID 4048 그대로 유지했다. `scripts/check_module_f_layout_live.py`로 정상 로그인 후 실제 F/H 초기 화면을 별도 브라우저에서 확인했다. F 5단계·새 화면 파일·업로드 표시, H 별도 UI가 정상이며 페이지 오류나 도면 변경 요청은 없었다. LAN 주소의 `/login`도 HTTP 200을 확인했다.

[F-10f] 이상 표시 — 전수 검수 대신 · 수용기준: PASS(부속·등가길이는 자리 없음 — 사유 표시)

전사 25:25 「30개에 해당 안 되면 굳이 필요가 없을 수도 있어. 불필요한 작업이잖아」
· 27:36 「클릭을 다 클릭을 하는 것도 불편할 수 있거든」 · 27:41 「뭔가 좀 이상하면
표시를 해서 확인을 해서 수정을 하고」.

집계 숫자로만 있던 것을 **항목** 으로 내렸다. 「확인할 것 n건」 목록에서 항목을
누르면 캔버스가 그 자리로 옮겨 가 겹고리로 강조한다. 목록이 0 이면
「확인할 이상 없음」 — 이것이 사람 검수의 완료 신호다.

■ 새 계산을 하나도 안 만들었다

전부 이미 화면에 와 있는 자료다:

    관경 별표1 폴백    배관 행의 `src == "nfpc_fallback"`   (배관별로 있다)
    유령              채택 결과의 skipped                  (mm 좌표)
    제외 사유 3갈래    F-5 의 `marks` (물길 미도달·이음 끊김·찍히지 않음)
    부속 판정 불가     요약 수치 그대로
    등가길이 미해결    요약 수치 그대로

그래서 **서버를 한 줄도 안 바꿨다.** 산출물이 안 변한다는 것이 자명하고
(D-F10-7), 목록 합계가 요약 집계와 어긋날 수도 없다 — 같은 자료의 두 얼굴이다.
목록이 제 계산을 하면 그 순간 두 수가 갈릴 수 있어 일부러 피했다.

■ 자리를 모르는 것은 그렇게 말한다

부속 판정 불가·등가길이 미해결은 엔진이 **개수만** 센다(`fitting.py` 의
`unresolved_kind`/`unresolved_length` — per-item 기록이 없다). 엔진은 이번
지시서에서 읽기 전용이므로 자리를 지어내지 않고 「자리를 특정할 수 없습니다 —
엔진이 개수만 셉니다」라고 적었다. 클릭 대상도 아니다.

■ 조사 중 잡은 결함 — «안 재고 없다고 말하기»

처음 구현은 표를 확정하지 않은 세션에서도 「확인할 이상 없음」이라고 적었다.
그것은 완료 신호를 위조하는 것이다(저장소 규약: 정직한 진행 표시). 표가 없으면
「표를 확정하면 확인할 것이 여기 모입니다」로 바꾸고, 그 규약을 시험과 브라우저
검증 양쪽에 못 박았다.

■ 이미 있던 것

corridor 위 «개별 색» 은 이미 있었다 — 관경 근거 색 나누기(`BORE_STYLE`,
별표1 폴백은 회색 점선). F-10f 가 더한 것은 **목록·이동·강조**와 완료 신호다.

■ 수용 기준

  [PASS] 관경 폴백 배관이 corridor 위에 개별 색으로 보인다 (기존 BORE_STYLE)
  [PASS] 목록 항목 클릭으로 화면이 그 자리로 이동한다
         — 좌표계가 둘이라(설계 vs 평면) 먼저 맞는 화면으로 돌린 뒤 옮긴다.
           안 그러면 엉뚱한 자리를 비춘다.
  [PASS] 이상 목록의 합계가 요약 집계와 일치한다
         — 같은 자료를 쓴다(새 계산·새 API 호출 없음)는 것을 시험이 못 박는다.
  [PASS] 마킹·목록은 표시 전용 — 산출물 불변
         — 서버 모듈에 이 기능의 자리가 아예 없음을 시험이 확인한다.
  [부분] 부속·등가길이는 «해당 배관 마킹» 을 못 한다 — 엔진에 per-item 기록이
         없고 엔진은 읽기 전용이다. 개수와 사유만 적었다.

목록은 40건까지 보이고 남은 수를 적는다 — 조용히 자르지 않는다(저장소 규약).

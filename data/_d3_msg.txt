PIPENET 없이 그린 도면에도 숫자는 결과 XML 원문 그대로 — ISO 벡터 PDF (모듈 D3)

D1 이 읽은 화면과 D2 가 결합한 결과를 A4 한 장짜리 벡터 PDF 로 옮겨 그린다.
계산은 한 줄도 하지 않는다. 표시할 값은 XDSET 원문을 SDF <Units> 의 자리수로
찍을 뿐이고, XML 에 없는 값은 0 으로 때우지 않고 빈칸으로 두고 리포트에 싣는다.

표시 항목을 바꿔도 도형은 한 톨도 달라지지 않아야 한다(지시서 6). 두 군데가
이 조건을 깨고 있었다.

- 범례 칸을 쓰는 만큼만 잡았더니 유량본은 한 줄, 압력본은 두 줄이 되어 그림틀
  높이가 달라졌다. 같은 망이 프리셋마다 다른 축척으로 나와 두 장을 겹쳐 볼 수
  없다. 쓰든 안 쓰든 두 줄을 비워 고정한다.
- 노드 마커를 밴드별로 나눠 그렸더니 도형 지문이 프리셋마다 한 점씩 어긋났다.
  matplotlib 은 점이 여럿인 마커 그룹은 form XObject 로, 한 점짜리는 인라인
  베지어로 방출한다 — 밴드 인원수가 바뀌면 PDF 안 표현이 흔들린다. 색 배열을
  실은 단일 scatter 로 합쳐 자리를 못 박았다.

색은 자체 분류다. SDF 스킴 요소 4690 개가 전량 auto-classify="1" 이라 경계값이
파일에 없다. PIPENET 색을 흉내 내는 대신 6 단계로 나누고 범례에 경계를 적는다.

검증 — 만든 PDF 에서 글자를 도로 뽑아 XML 원문과 1:1 로 맞춰 봤다. 환산 계수는
검증기에 다시 적었다. 렌더러 상수를 돌려 쓰면 계수가 틀려도 양쪽이 똑같이 틀려
통과해 버린다.

- 제출용 2 파일 × 프리셋 3 종 — 불일치 0 (hand 관로 103·노드 104, auto 136·137)
- 참조 코퍼스 52 파일 2450 개 관로 압력 라벨 — 불일치 0
- 코퍼스 260 쌍 렌더 — 실패 0, 장치 링크 504 개, 94.6s (0.36s/장)
- 도형 지문 3 프리셋 완전 동일, 텍스트는 전부 상이
- PNG 150dpi 로 육안 확인 — 망·표제란·범례·한글 정상
- pytest tests/test_module_d -q → 50 passed

검증 중 코퍼스 대조가 1908 건 어긋나 렌더러를 의심했으나 틀린 쪽은 검증기였다.
XDSET 은 파일마다 압력을 Pa 로도, kg/cm² 로도 적는다. D2 의 배율 실측이 이미
이를 흡수하고 있었고, 검증기만 SI 를 가정하고 있었다.

좌측 밀집 구역의 라벨 겹침은 남아 있다. D4 가 맡는다.

# 모듈 F 수리계산 입력 성능 개선 (2026-09-16)

대상은 로컬 5051의 수동 경로, 손질에서 선정한 헤드를 수리계산 입력표로 확정하는 단계다. 이전 DXF 업로드 개선과 별도의 작업이다.

## 원인과 변경

1. 선택한 헤드 10개를 확정할 때도 전체 도면의 연결 가능 헤드를 전개했다. 이제 선택된 헤드의 연결을 검사하고 선정망만 전개한다. 전체 도면의 이음 끊김·제외 사유는 **전체 도면 진단** 버튼으로 확인한다. 진단 전에는 제외 개수를 0으로 단정하지 않고 미진단으로 표시한다. 선정 없이 호출하는 기존 API 경로는 전체 검사를 유지한다.
2. 교차 검사에 들어오는 좌표는 m인데 격자 크기가 mm 기준 2000이었다. 2m 격자로 바로잡고, 전체 쌍을 저장하던 집합을 배관별 후보 집합으로 바꿨다. 큰 이상치 선분은 격자 생성량을 제한하고 bbox로 비교한다. 기존 교차 판정식과 정렬은 유지한다.
3. 부속 판정용 연결 차수 계산이 좌표 구역마다 모든 배관을 훑었다. 각 배관을 한 번 순회해 양 끝의 서로 다른 구역에 기여도를 더하도록 바꿨다. 같은 구역 내부 배관, 중복 배관, 좌표 없는 끝점의 처리도 기존 XOR 규칙과 같다.

전체 진단 캐시의 지문은 마지막 좌표 세 개 대신 전체 좌표·간선·길이 정보를 포함한다. 도면 중간을 고친 뒤 옛 진단 결과가 재사용되는 경우를 막는다.

## 실제 도면 측정

`B1F 현장조사 소화설비 평면도_컨셉2` 저장본을 격리 복사해 측정했다. 헤드 6,896개, 지정 영역 `[655000,165000,675000,180000]`, K=10, 알람밸브 인근 `(662692,175774)`를 사용했다. 사용자 원본·저장된 선정을 수정하지 않았다. 원본 문자 캐시에서 관경 문자 1,108개를 읽었다.

| 단계 | 측정 시간 |
| --- | ---: |
| 영역 내 최불리 10개 선정 | 1.81초 |
| 선정 헤드 연결 검사부터 입력표 확정 | **7.53초** |
| 선택적으로 실행한 전체 도면 진단 | 23.37초 |
| 전체 진단 안의 교차 검사 (배관 16,288개 / 교차 194개) | 0.31초 |
| 전체 검사 결과를 캐시한 기존 확정 경로와 결과 비교 | 6.55초 |

마지막 행은 기존 전체 검사의 최초 비용을 제외한 비교 실행이다. 최적화 전 전체 시간을 같은 조건에서 재측정한 값이 아니므로 단축률을 계산하지 않는다. 측정값은 이 영역·장비·캐시 상태의 결과이며 도면과 선정 범위에 따라 달라진다.

## 계산 결과 보존 및 검사

- 실제 도면에서 선택 범위 검사 경로와 기존 전체 검사 경로의 노드·배관·노즐·부속·기기 5개 표가 완전히 일치했다. 노드 59개, 배관 58개, 헤드 10개, 총 길이 165.43m다.
- 표 SHA256: `52119e0dc2c347c2d7cb2ba3399ce3c0e45d1e7eb89ac91b83265236b01d654d`.
- 별도 전체 진단 전후에도 위 5개 표와 최불리 선정이 동일했다. 합성 통합 시험에서는 SDF 파일 바이트까지 같았다.
- 선정 헤드 중 연결되지 않거나 중심을 공유하는 헤드가 있으면 확정을 차단한다. 후보 축소, 다른 헤드로 채우기, 손질 선정 되먹임을 하지 않는다.
- 무작위·음수·격자 경계·공유 끝점·긴 대각선의 교차 검사를 독립적인 전수 비교와 대조했다. 연결 차수도 전수 XOR 비교와 같았다.
- 관련 회귀 검사 **147건 통과**. JavaScript 구문 검사 및 `git diff --check` 통과.
- 실제 도면의 기존 미해결 부속 2건·등가길이 1건은 동일하게 남는다. 성능 개선이 설계값을 추정해 채우지 않는다.

[F-11e] 줄바꿈 규약을 파일로 못 박는다 (+ preview 404 확인) — 수용기준: PASS

■ .gitattributes 신설 — **실내용 변경 0**

규약이 «사람마다 다른 git 설정» 에 달려 있었다. 이 저장소는 `core.autocrlf=true`
인 기계에서 커밋되어 왔고, 그래서 지금 이렇다:

    추적 파일 2,326개 중 903개가  i/lf  w/crlf   (저장소 LF · 작업본 CRLF)

설정이 다른 기계에서 clone 하면 그 903개가 통째로 «변경됨» 으로 뜬다 — 내용은
한 글자도 안 바뀌었는데. 규약을 파일로 적어 그 사고를 막는다.

★지시서가 요구한 증명, 실측:

    git add --renormalize .          →  스테이징된 파일 **0개**
    git diff --cached --ignore-cr-at-eol  →  **0개**

  이 커밋은 규약을 적어 둘 뿐 파일을 하나도 안 건드린다.

★`eol=lf` 를 일부러 안 썼다. 그것을 쓰면 작업본까지 LF 로 바꿔 903개가 다음
  checkout 에 전부 다시 써지고, Windows 편집기로 여는 사람이 곤란해진다.
  `text=auto` 는 «저장소에 넣을 때만» 정규화하므로 지금 동작과 정확히 같다.

바이너리는 확장자로 못 박았다. 안 적으면 git 이 내용을 보고 추측하는데,
추측이 틀리는 날이 «파일이 깨지는 날» 이다.

■ ★안 한 것과 그 이유 — DXF·SDF·SLF 의 `-text`

처음에 이 형식들에 `-text` 를 걸었다가 **뺐다.** 걸어 보니 이렇다:

    -text 를 걸고 renormalize  →  16개 파일의 blob 이 LF → CRLF 로 바뀜

즉 이 파일들은 이미 커밋 때 LF 로 정규화되어 저장돼 있고, checkout 때 CRLF 로
풀린다. PIPENET 은 Windows 프로그램이라 원본이 CRLF 였을 가능성이 높으므로,
저장된 레퍼런스는 벤더 원본과 줄바꿈이 다를 수 있다.

고쳐야 하는지는 **재 봐야 안다** — 골든 비교가 파일을 바이트로 읽는지,
PIPENET 이 LF 를 받아들이는지. 안 재고 16개 blob 을 바꾸면 이 커밋의 조건
(「실내용 변경 없음」)을 스스로 깨는 셈이라 손대지 않고 `.gitattributes`
주석에 숙제로 적어 뒀다.

■ 곁들여 — F-11e-1 은 이미 해소돼 있다 (확인만)

`/design/preview` 의 «아직 확정 안 함» 은 404 가 아니라 200 + `view: null` 로
답한다(§18-3 · 커밋 895a9cd). 화면도 `if (!d.view) { if (d.message) say(...) }`
로 분기한다. 완주 검증 로그에 **콘솔 404 0건**. 새로 할 일이 없어 기록만 한다.

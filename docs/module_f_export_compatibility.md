# 모듈 F 출력 호환성 보정 (2026-09-17)

## 재현 자료와 확인한 원인

사용자가 제공한 `module_f_merged_iso (1).sdf/.kfp`와 `module_f_merged_iso.slf`를
분석했다. SDF는 서버의 `data/module_f_merged/9fe96c8635c5404f/` 산출과 일치한다.

1. SDF의 마지막 헤드 배관 30개는 이미 수직 하향이었다. 그러나 노즐 입력 절점과
   `@/` 대기 출구 절점의 표시 좌표가 같아 PIPENET 기호가 옆을 향했다.
2. 실제 PIPENET 로그는 형식 검사 통과 뒤 11번 절점이 한 요소에만 연결되어 있으나
   I/O 조건이 없다는 이유로 중단됐다. 15번도 같은 조건이었다.
3. 통합 KFP는 30도 아이소가 적용된 SDF의 Position을 XYZ의 XY로 읽었다.
   Solver의 아이소 투영이 다시 적용되고, 화면 배치 거리가 실제 배관 거리로
   섞이면서 수직 입상관과 말단 형상이 비틀렸다.

## 수정 범위

- F의 수리계산 입력 SDF와 통합 SDF 양쪽에 `prepare_sdf_export`를 적용한다.
  A/E/G의 기존 호출 경로에는 자동 적용하지 않는다.
- 노즐의 독립 대기 출구를 입력 절점과 다른 위치로 표시한다. 말단 헤드와 부모의
  실제 표고차로 상/하향을 정한다. 배관 방향이 반대로 저장돼도 같다.
  표고차가 없거나 배관이 여러 개 연결된 경우 기존 방향을 유지하고 진단에 남긴다.
- 배관 하나에만 연결되고 경계조건이 없는 수요 없는 끝은 `Output`과 `flow=0`으로
  명시한다. 노즐 출구, 다른 기기 연결, 기존 압력/유량 조건은 덮어쓰지 않는다.
  배관·노즐의 길이, 상승고, 관경, 유량, 연결과 실제 표고는 바꾸지 않는다.
- 통합 KFP는 아이소 적용 전 SDF의 방향, 배관별 지정 길이, 실제 표고를 사용한다.
  수직 배관은 XY가 동일하다. 평면/아이소 KFP는 같은 실제 XYZ를 담는다.
  일반 SDF→KFP 변환의 기본 동작은 유지하고 F가 검증된 실제 좌표 옵션을 사용한다.
- 모든 실제 배관과 중간 코너를 보존한다. 루프 닫힘은 5mm 허용오차로 검사하고,
  모순·분리된 망·방향 없는 수평관·길이보다 큰 표고차는 KFP 오류로 보고한다.
  루프를 잘라 트리로 만들거나 배관 길이를 덮어쓰지 않는다.
- SDF의 같은 표고 펌프 양끝은 KFP의 인라인 펌프 한 절점으로 표현한다.
  화면용 간격에서 임의의 토출 배관 길이를 만들어 추가하지 않는다. 서로 다른
  표고/기기/경계조건을 가진 펌프 끝은 자동 병합하지 않고 명시적으로 거절한다.

계통도의 수평구간 방위는 실도면 방위가 없으면 기존 아이소 적용 전 표시 방향을
따른다. 배관 지정 길이와 표고는 보존되지만 이 방위가 실제 건축 위치라는 뜻은 아니다.
Waypoints가 있는 굽은 배관은 실제 코너 절점으로 분리한 후 KFP로 내야 한다.

## 실제 프로그램 검증

- 별도 SDF/SLF를 PIPENET 1.80에서 열어 헤드가 수직 하향으로 표시됨을 확인했다.
- PIPENET 계산이 5회 반복 후 수렴했다. 상태는 `Failed`에서 `Warnings`로 바뀌었다.
- 계산 입력 사본과 수정 SDF의 배관 256개 및 노즐 30개의 연결·길이·상승고·관경·C·상태를
  비교했고 차이가 없었다. 경계는 m1의 원래 압력과 11/15번의 0유량이다.
- 남은 경고는 P23, P59, P75, P78, P98, P99의 유속 초과다. 수치 기준이나 관경을
  임의로 완화하지 않았다. 이는 계산 중단 오류와 별도로 설계자가 검토할 사항이다.
- 보정 KFP를 K-Fire Hydraulic Solver 5.5에서 열어 헤드 30개와 수직 입상관을 확인했다.
  KFP에 대한 별도 수리계산 완료를 의미하지는 않는다.
- 원본 파일은 보존했다. 원래 실패 로그, 보정 계산 로그와 실제 계산 입력은
  `data/export_validation/20260917/`에 있다.

[F-11b] 직접 입력 화면 완성 — 지우는 길 · 재확정 배지 · 표의 얼굴 · 수용기준: PASS

§18 에서 서버는 끝나 있었고 화면도 «채우는» 데까지는 서 있었다. 남은 세 자리를
잇는다. 서버 코드는 이 항목에서 **한 줄도 안 바꿨다**(지시서 F-11b 수용기준).

■ ★① 지우는 길 — 막다른 길 0 (F-11b-4)

서버는 「빈 배열을 보내면 지운다」를 이미 규약으로 갖고 있었는데 **그것을 부를
단추가 화면에 없었다.** 사람에게는 없는 기능이다 — 한 번 잘못 채우면 그 값에
갇힌다. §0.1 의 «완결성»(표시된 모든 한계에 프로그램 안에서 고칠 길이 있다)이
여기서 깨져 있었다.

「직접 입력 — 사람이 채운 자리」의 각 항목에 「직접 입력 지우기」를 단다.
지우면 그 자리는 다시 미해결로 돌아가 목록에 재등장한다.

★지울 때 **다른 갈래는 안 보낸다.** 서버 규약이 「칸을 안 보내면 그대로,
  빈 배열이면 지운다」이므로, 둘 다 보내면서 한쪽을 빈 배열로 두면 부속을
  지울 때 등가길이까지 날아간다. 시험이 이 성질을 소스로 못 박는다.

■ ★② 재확정 배지 — 세우는 곳이 없었다 (F-11b-2)

「표를 다시 확정해야 값이 들어간다」 배지의 그리기 코드는 있었는데 `S.ovDirty`
를 **세우는 곳이 어디에도 없었다** — 뜰 수 없는 배지였다. 게다가 세워 놨어도
바로 뒤의 `countFilled()` 가 같은 칸에 「채운 칸 0」을 써서 지웠을 것이다.

  · 세운다 — 저장·지움 두 경로에서 서버의 `needs_rebuild` 를 그대로 쓴다.
  · 내린다 — 재확정이 **성공한** 자리에서만. 실패로 빠지는 throw 뒤에 두어,
    재확정이 깨지면 배지가 남아 「저장했지만 아직 안 들어갔다」를 말한다.
  · 배지 칸에 쓰는 곳을 `countFilled` **한 곳**으로 모았다. 두 곳에서 쓰면
    나중 것이 앞 것을 덮는다 — 실제로 그러고 있었다.

채울 칸이 하나도 안 남아도(다 채웠어도) 배지 줄은 서 있어야 한다. 그래서 줄을
세우는 조건이 `fillable` 에서 `fillable || S.ovDirty` 가 됐다.

■ ③ 표에서도 «직접 입력» 이 다른 얼굴 (F-11b-3)

목록에는 「직접 입력 — 사람이 채운 자리」 무리가 있었지만 **부속표** 행은
자동 값과 같은 얼굴이었다. 엔진 부속표에는 그 칸이 없고 이 항목에서 서버는
불변이므로, 화면이 **이미 받아 둔** `unresolved.applied` 를 표에 겹쳐 놓는다 —
새 판정이 아니라 표시다(개수는 여전히 엔진 한 곳에서만 나온다).

채운 자리가 있을 때만 「근거」 칸이 서고, 없으면 표를 안 건드린다.
맞춤은 (배관, 종류) — 부속표 행에 «어느 노드인지» 가 없어 더 좁힐 수 없다.
한 배관에 같은 종류가 둘이면 둘 다 표시된다. 주석에 그렇게 적었다: 넓게
보이는 쪽이 «채운 걸 안 보여 주는» 쪽보다 정직하다.

■ 수용 기준 — 대명동 실측 (scripts/_probe_f11b_override.py)

    ① 처음      부속 판정 불가 4건 · 직접 입력 0
    ② 저장      kind 1 · 재확정 필요 True
    ③ 재확정 전 부속 판정 불가 4건  ← 아직 안 들어감(배지의 근거)
    ④ 재확정 후 부속 판정 불가 3건 · meta「직접 입력 — 부속 판정」1
                └ P12 · none · 사유 「도면에서 직선으로 확인」
    ⑤ 지움      kind 0
    ⑥ 재확정 후 부속 판정 불가 4건 · 직접 입력 0        [복귀]

★지시서가 적은 수치는 「3 → 1건 채움 → 2」인데 여기서는 **4 → 3 → 4** 다.
  최불리가 달라서다(이번 앵커는 최원 50.71 m, F-11a 때는 45.74 m) — 부속
  판정 불가는 «선정된 30개 범위 안» 을 세므로 앵커가 바뀌면 개수도 바뀐다.
  줄고·늘어나는 «모양» 은 지시서 그대로이고, 절대 수치만 다르다. 앵커를
  고정하지 않은 것은 이 프로브의 한계다 — 그대로 적어 둔다.

고를 수 있는 종류는 서버가 4가지를 준다: 직선 — 부속 없음 · 45° 엘보 ·
90° 엘보 · 티 (자유 입력 금지, §18 실측 근거).

■ 검증 — 화면을 «부른다»

구문 검사만으로는 안 잡히는 회귀가 이 코드에 산다(함수-지역 헬퍼를 다른
스코프에서 부르면 ReferenceError 로 화면만 조용히 빈다). 그래서 브라우저
검증이 엔진이 내는 그 모양의 표를 넣고 **진짜 그리기 함수를 부른다** —
`window.__mf` 로 상태를 내던 기존 규약에 그리기 함수 셋을 더했다.

    [OK] 못 가린 자리에 고르는 칸이 붙는다      종류 1 · 등가길이 1
    [OK] 채운 자리에 «지우기» 가 붙는다          2개
    [OK] 채운 자리가 목록에서 구별된다
    [OK] ★재확정 전에는 배지가 사실을 말한다     warn=True
    [OK] 배지가 「채운 칸」을 덮어쓰지 않는다
    [OK] 부속표에 «근거» 칸이 선다               2행 · 직접 입력 — 부속 · 도면에서 확인
    [OK] 채운 것이 없는 표는 안 건드린다
    [OK] 콘솔 오류 없음

# Module H 영역 배관망 + 급수 경로 추출

## 수정 이유

이전 루프/그리드 추출은 영역 안의 헤드만 고른 뒤, 급수원부터 해당 헤드로 가는 **모든 단순 경로**를 남겼다. 선택 영역 밖의 큰 순환망까지 같은 이중연결 성분에 속하면 전부 추출되는 동작이었다.

사용자 확인에 따라 Module H의 `area_all`은 `region_and_supply_v1` 정책을 사용한다. Module F의 기존 K개 선정, 전체망 출력, 트리 방식은 바꾸지 않는다.

## 범위 규칙

- 영역 안의 정의된 헤드는 모두 선정한다. 누락·미연결은 기존처럼 명시적 오류로 보고한다.
- 원본 공급망 중 지정 영역과 겹치는 배관을 남긴다. 영역 안의 실제 루프와 분기 연결은 유지한다.
- 각 지역 연결 성분에 대해 기존 공급 기준 경로 하나를 추가한다. 우선순위는 기존 기준과 동일하게 추정 연결 수, 명시된 길이, 구간 수, 절점 번호 순이다. 전역 최단 Steiner 망이나 수리적 최불리 경로를 계산하는 기능이 아니다.
- 외부의 모든 우회 경로를 다시 전개하지 않는다. 교차하는 선을 새 접속점으로 만들지 않는다.
- 경계에 걸친 배관은 원본 구간 단위로 보존한다. 영역 경계에서 임의로 새 절점·손실·길이를 만들지 않으며 `boundary_edges`로 따로 기록한다. 따라서 경계 밖으로 다음 원본 절점까지 소폭 남을 수 있다.
- 이 추출은 사용자가 지정한 부분망이다. 외부 우회 경로가 제외되므로 전체 시설의 수리해석과 동등한 망으로 간주하면 안 된다. 기존 미확정/검토용 출력 표시와 수리 검증 요구를 유지한다.

## 일관성 및 검증

화면 경로, 입력표, 선정망 KFP/SDF, 경로 보고서가 동일한 원본 간선 집합을 사용한다. 진단용 최원 경로도 제한된 망에서 다시 산정한다. 기존 범위 정책으로 만든 선정 또는 간선이 바뀐 선정은 재추출하도록 차단한다. 물리적인 부속 포트는 기존 원본 망에서 별도로 유지한다.

핵심 구현: `src/pipenet_converter/graph/area_network.py`.

회귀 검증: `tests/unit/test_area_network.py`, `tests/test_module_h_area_selection.py`. 영역 안 루프 보존, 외부 루프 제외, 원본 연결 보존, 다중 영역, 오목 다각형, 0길이 별칭, 표/출력 일치, 기존 F 정책 보존을 검사한다.

현재 화면과 동일한 원본 공급망 지문 `1a96530e70b75be7`, 급수 절점 520, 영역 내 헤드 84~91을 재현했다.

`scripts/audit_area_network.py`는 원본 캐시를 읽어 복사본에서만 비교하며 원본 DXF, 사용자 편집, 실행 중 세션을 변경하지 않는다. 결과는 `outputs/mf20_area_review/`의 `report.json`, `selected-network.json`, `selected-model.json`, `comparison.png`에 저장했다.

## 검증 결과

관련 최종 묶음은 175개 통과, 6개 선택 실행용 검사 건너뜀이다. 새 H 브라우저 검사에서는 평면/등각 전환 전후 입력표와 원본 간선 집합이 같음을 확인했다.

넓은 검사에서 `test_module_f_cycle_closures.py::test_browser_shows_recovered_connection_and_review_count`는 기존 F 화면의 숨겨진 `#ed-network-mode`를 선택하려다 실패했다. 이 테스트는 영역 추출을 호출하지 않는 UI 검사이며, 위 최종 묶음에서는 별도로 제외했다. 전체 테스트 무결점 통과를 의미하지 않는다.

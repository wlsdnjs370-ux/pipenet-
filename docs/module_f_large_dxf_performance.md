# 모듈 F 대용량 DXF 처리 최적화 — 2026-09-16

## 변경

- 삼각형 헤드를 찍을 때 같은 레이어·색상 묶음의 군집과 닫힌 삼각형을 다시 계산하던 작업을 Board 수명 동안 재사용한다. 크기자·허용오차·라벨 판정은 기존 `tri_head_of`가 수행한다. 군집 조건과 허용오차가 바뀌면 캐시를 구분한다.
- 삼각형 선분의 접점, 헤드 주변 노드, 끊어진 배관 주변 헤드를 공간 색인으로 조회한다. 최종 거리·각도 판정과 동점 순서는 보존한다.
- 방향 조건상 탈락이 확정된 선분은 두 번째 각도 계산을 생략한다. 경계의 각도 계산은 기존 함수를 사용한다.
- 모듈 F 작업 로그에 헤드 채택 소요 시간을 표시한다.

모듈 A 인식 기준, 모듈 E, 도면의 건축 요소, 헤드 선정 규칙은 수정하지 않았다. F가 사용하는 G 엔진을 수정했으므로 G의 같은 엔진 호출에도 적용된다.

## 검증 및 재현

`tests/test_module_f_spatial_speed.py`는 전수 탐색과 색인 탐색의 결과를 비교한다. 음수 좌표·셀 경계·여러 반지름·거리/각도 경계·헤드 동점 순서·서로 다른 삼각형 크기·캐시 조건 변경을 포함한다. 기존 통과관 접속, 업로드, 채택, 헤드 종류, 재료 변경 회귀를 포함한 197개 검사를 통과했다.

첫 검사 실행에서는 백그라운드의 선택적 pandas/pyarrow 최초 import가 Windows 네이티브 진단을 출력했다. 테스트 실패는 없었지만 검증 환경 문제를 구분하기 위해 pandas를 메인 스레드에서 먼저 import한 뒤 재검사했고, 해당 진단 없이 **197 passed in 7.18s**를 확인했다. 라이브 업로드는 별도로 확인한다.

```powershell
python -X utf8 scripts/benchmark_module_f_upload.py 'data/uploads/B1F 현장조사 소화설비 평면도_컨셉2.dxf' --baseline b1c1cc3 --graph --output cad_project_editor_g/docs/benchmarks/upload_before.json
python -X utf8 scripts/benchmark_module_f_upload.py 'data/uploads/B1F 현장조사 소화설비 평면도_컨셉2.dxf' --graph --output cad_project_editor_g/docs/benchmarks/upload_after.json
python -X utf8 -m pytest -q tests/test_module_f_spatial_speed.py tests/test_attach_pass_under.py
```

비교 스크립트는 G 폴더 아래 임시 작업폴더를 사용하고 종료 시 정리한다. `--baseline`은 작업 파일을 교체하지 않는다. `--profile`은 별도 성능 분석용이며 위 시간 비교에는 사용하지 않았다.

[리팩터링 7/n] 급수원과 알람밸브는 같은 장치였다 — 픽 하나·뿌리 하나·이름 하나

「알람밸브랑 급수랑 구조적인 차이가 존재할까? 둘 다 똑같은 시작 노드 아니야?」
— 맞았다. 그리고 **통합 엔진은 진작 그렇게 가정하고 있었다.**

  core/remote30_full_network.py
    _COORDS_AV = (100, -3300)   # 노드 10 (헤드망 source ★)
    av_node_label: str = ""     # 라이저 끝점 = 헤드망 source 와 stitch 할 라벨
    if n["label"] == av_lbl: continue   # AV 는 라이저 쪽에서 이미 포함 —
                                        # 헤드망 쪽 사본 skip
  merge.ANCHOR_LABEL="10" · LABEL_OFFSET=9 도 평면도 BFS 뿌리(라벨 1)를 라이저의
  알람밸브 노드 자리에 정확히 떨어뜨리려고 잡은 값이다.

즉 평면도의 «급수원» 은 실체가 알람밸브 자리이고, 통합하는 순간 라이저의 AV
노드에 자리를 내주고 사라진다. 진짜 수원·펌프는 기계실에서 온다.
그런데 화면·데이터는 옛 가정에 남아 있었다 — 같은 장치를 두 번 찍게 했다.

■ ① 평면도 픽을 하나로 (B1 해소 — 종전 D-F10-4 는 «공존 유지» 였다)

  손질 모드에서 «급수 시작» 을 없앴다. 알람밸브 픽이 접속점을 겸한다
  (`session.click`: 한 픽 → valves + sources 동시). 따로 찍을 수 있으면
  어긋날 수 있고, 어긋나면 Input 경계와 알람밸브가 다른 자리에 놓인다.
  · 은퇴한 «급수시작위치» 모드는 «모르는 모드» 로 막지 않고 **같은 동작**으로
    받는다 — 옛 화면이 보내도 어긋남을 만들 수 없다.
  · 되돌리기도 한 번이면 된다. 종전엔 두 번 눌러야 했고, 한 번만 누르면
    «접속점 없는 알람밸브» 라는 중간 상태가 남았다.
  · 제안 반영 단추도 하나로. 자동 차선은 **진작** handoff 의 alarm 과 source 에
    같은 좌표를 넣고 있었다(`api_auto`: "source": list(alarm)).

■ ② 뿌리 찾기 — 조용한 폴백을 걷어낸다 (design/anchor.py 신설)

  종전 두 곳(`design/tables.py` · `design/restrict.py`)이 똑같이
  「접속점을 못 찾으면 `next(iter(nodes))`」 로 눕었다. dict 에 먼저 들어온
  노드가 Input 경계가 되고 물 흐르는 방향이 통째로 거기서 유도된다 — 사람이
  찍은 자리와 아무 상관 없는 지점에서 계산이 시작되는데도 표는 틀렸다고
  말해 주지 않는다. 이제 `require_anchor` 가 사람이 읽을 문장으로 던진다.
  (`n_src` 를 세기만 하고 검사하지 않아 펌프 0개가 통과할 수 있었다.)

  ★저장된 표식 `type_id="pump"` 는 그대로 둔다 — 바꾸면 기존 .kfp 가 접속점을
    잃는다. 데이터는 두고 **부르는 이름만** 바로잡았다.

■ ③ 등가길이 — 채울 자리를 하나로 (fitting.resolve_eq_len)

  ★실측 결함: 기기표의 알람밸브 행이 `"eq_len": 0.0` 으로 박혀 있었다.
    라이브러리에 값이 **버젓이 있는데도**(알람밸브 100A = 9.5 m) SDF 에는 0 이
    실렸다. 0 은 「손실이 없다」는 주장이라 그만큼 계산이 낙관적으로 틀어진다.
    (앞서 「라이브러리가 전부 null」이라 한 것은 내 오독이었다 — 15~40A 만 보고
     일반화했다. 65~150A 에는 값이 있다.)
  이제 부속표와 기기표가 같은 함수를 쓴다: 라이브러리 → 사람이 채운 값 → 미해결.
  못 구하면 0 으로 때우지 않고 「등가길이 미해결」과 목록에 넣는다.
  실측: 100A → 9.5 m(근거 라이브러리) · 15A → 미해결 1건으로 신고.

■ ④ 「앵커」가 정반대 두 곳을 가리키던 것을 갈랐다

  ① 접속점(라이저가 붙는 자리, 물이 들어오는 쪽)  ← 「앵커」는 이제 이것만
  ② 급수에서 가장 먼 헤드(기준압 지점)            ← «기준 헤드» 로 개명
  망의 입구와 가장 먼 출구를 같은 낱말로 부르면 읽는 사람이 매번 되짚어야 한다.
  수리계산에서 가장 헷갈리면 안 되는 두 지점이다.
    worst["anchor"] → ["worst_head"] · anchor_path → worst_path (+_m)
    meta 「앵커 노드」 → 「기준 헤드 노드」 · _anchor_node → _worst_head_node
  라우트(`/auto/anchor` · `/edit/anchor-click`)와 `merge.ANCHOR_LABEL` 은 원래
  ①이므로 그대로 둔다 — 이제 그 이름이 정확해졌다.

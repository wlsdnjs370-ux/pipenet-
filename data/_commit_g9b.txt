[G9·G11] 배관 규격 바인딩과 좌표 정규화 — 수용기준: PASS

PIPENET 에서 연 산출물의 결함 세 가지를 고친다. 위상(Node 92·Pipe 61·Nozzle 30)은
정상이었고 **직렬화만 틀렸다**.

■ 증상 1 — Pipe 표 Type 이 전부 "None defined"
  `pipenet_converter` 의 writer 가 `<Pipe-type>` 을 아예 안 쓴다. `Pipe.material` 을
  받아만 두고 버린다. 표에는 값이 있었다(`tables.py` 가 "KSD 3507" 을 채운다) —
  **표에서 죽은 게 아니라 XML 에서 죽었다.**
  → writer 를 고치면 모듈 A·F 산출물까지 흔들리므로(§3) **방출 후처리**로 얹었다.
    `design/sdf_post.py:inject_pipe_types` — 모듈 A 와 같은 방법.
    실측: Pipe-set 2개(placeholder+파이프) → **7개**
      [빈 placeholder] KSD 3507(61) KSD 3562 KSD 3576 DP CPVC2 FX
    안 쓰인 5종도 «Pipe-type 만 있고 Pipe 없는» Pipe-set 으로 둬 PIPENET 드롭다운에
    노출된다 — 이것이 「라이브러리를 가져오게 한다」의 실제 내용이다.
    ★맨 앞 빈 placeholder 를 유지한다. 없으면 우리 Pipe-type 이 blank 슬롯에
      흡수돼 관경이 "Unset" 이 된다.
    스케줄 이름은 SLF 의 Item-name 과 철자·공백까지 같아야 바인딩된다 —
    자산 파일에 6종이 다 있는지 검사가 확인한다.

■ 증상 2 — 망이 캔버스 한 점에 뭉침
  `tables_to_network` 가 좌표를 /1000(mm→m)만 했다. B1F 는 한 변이 수백 m 라
  ±100 대 실수가 되어 스키매틱에서 사실상 한 점이다.
  → `normalize_node_coords` 로 bbox 중심→(0,0), 가장 긴 축→3000 unit.
    /1000 은 **제거**했다 — 정규화가 이미 스케일을 흡수하므로 두 번 나누면 다시
    뭉친다. 실측 노드 좌표 폭 12,132 → **정확히 3,000**, 중심 (0,0).
    `display_z` 가 있으면 x,y 와 **같은 배율**을 곱한다.

■ 증상 3 — io-node 가 규약 밖
  writer 는 metadata 가 없으면 node_type("base")을 그대로 흘려보낸다. PIPENET
  규약은 "No"/"Input" 이다. → metadata 로 명시. 실측 io-node 값 {Input, No}, base 0건.

■ 회귀 — 표시만 바뀌고 계산은 그대로 (가장 중요)
  아이소매트릭 켬/끔, 캔버스 3000/8000 세 산출에서 **length·rise·elevation·bore·
  부속·노즐 유량이 완전히 동일**하다(배관 61·노즐 30). `<Position>` 만 달라진다.
  G1~G6(OK 89) · G7 창 통과.

■ 전체망 .kfp 기준선도 함께 고쳤다
  이번 확인에서 .kfp 기준선이 빨간불이었는데 **원인은 코드가 아니라 입력이었다** —
  작업 폴더의 표시 캐시가 다시 만들어져 board 가 바뀌었다(pts 19,040 → 19,791,
  BLOCKED B6). `_kfp_baseline.py` 는 emit·sdf_post 를 import 조차 하지 않으므로
  이번 변경이 닿을 수 없는 경로다.
  그런데 기준선이 그 둘을 같은 빨간불로 알리고 있었다 — 그러면 진짜 코드 회귀가
  났을 때 경고를 안 믿게 된다. **board 지문을 함께 기록해 「입력이 바뀐 것이지
  코드 회귀가 아니다」로 갈라 말하게** 했고, 일부러 어긋나게 해 그 경로가 실제로
  도는 것도 확인했다. 현 board 로 기준선을 다시 떴다(노드 662·배관 661).

## 1. 오너 지시

«계통도 파트에 B1F 도면을 로드할 때, 너무 시간이 오래걸리는데, 로직 좀 최적화를 시켜주겠어?»
→ 그림 37~39 로 계획을 보인 뒤 «①②③ 모두» 로 결정.

## 2. 무엇이 느렸나 (가상 PC 실측 · 서버 PC 는 약 1.3배)

| 단계 | 시간 |
|---|---|
| ① DXF 파일 읽기 (`ezdxf.readfile`) | 20.3초 |
| ② 도형 펼치기 (A `parse_dxf_for_view` 의 나머지) | 1.6초 |
| ③ 화면용 묶음 · ④ 레이어 표 | 0.5초 |
| ⑤ ★추적 그래프 (A `build_system_graph` — 조각 12,387개 잇기) | 7.4초 |
| 합계 — 도면은 ⑤ 까지 끝나야 떴다 | 약 30초 (서버 약 38초) |

- B1F 파일 116 MB 중 블록 정의가 85.8 MB(74%). 블록 1,532개 중 도면 본체에서 따라가 닿는 것은
  286개(2.3 MB)뿐이고 1,246개(83.5 MB)는 한 번도 안 놓인다. A 의 파서는 놓인 블록만 펼치는데,
  그 앞의 ezdxf 가 안 쓰는 것까지 전부 CAD 객체(38만 개)로 만든다.
- 같은 파일을 다시 올려도 처음부터 다시 읽었다(계통도 칸에는 기억이 없었다).

## 3. 바꾼 것 — 모듈 A 코드는 한 줄도 안 고쳤다

### ① 안 쓰는 블록 정의는 «속을 비운 사본» 으로 읽는다 (`routes/module_f/sub_fastread.py`)

- 파일을 글자로만 훑어(B1F 0.9초) 도면이 쓰는 블록을 찾는다: 도면 본체의 도형이 이름(그룹 코드 2)
  이나 번호(340~349 · 1005) · 글자(1000)로 가리키는 블록 → 그 블록 안이 또 가리키는 블록 → 끝까지.
  치수 스타일의 화살표 블록, 멀티지시선 스타일의 화살표·내용 블록도 따라간다.
- 도면 틀(*Model_Space · *Paper_Space)과 화살표 블록(이름이 «_» 로 시작)은 늘 남긴다. 멀티지시선이
  화살표를 따로 안 적으면 ezdxf 가 `_ClosedFilled` 를 **이름으로** 찾아 쓰기 때문이다 — 파일 안에
  가리키는 글자가 없다(합성 도면 시험에서 잡았다).
- 나머지 블록은 시작(BLOCK)·끝(ENDBLK) 표시만 남기고 속을 비운 임시 사본을 만들어 A 의 파서에
  그대로 넘긴다. 사본은 읽고 바로 지운다.
- **모르면 비우지 않는다**: 모르는 도형 종류(3D 솔리드 · 프록시 객체 …) · 이진 DXF · 줄끝 섞임 ·
  블록 짝 안 맞음 → 원본 그대로. 사본 읽기가 실패해도 원본으로. 블록 정의가 파일의 15% 미만이거나
  비울 몫이 10% 미만이면 사본을 안 만든다.
- 급할 때 끄는 스위치: 환경변수 `MODULE_F_SUB_STRIP=0`.

**확인 (도면 75장 · 1.5 GB)**: 사본으로 읽은 도형 목록 · 레이어 표 · 범위가 원본과 한 글자도 같음
— 비운 것이 있던 55장 전부 같음 · 비울 것이 없던 18장은 원본 그대로 · 모르는 종류가 있던 2장은
자동으로 원본 · **다름 0장**. A 가 원본을 읽으며 연 블록은 전부 «쓰는 블록» 안에 있었다.

| 도면 | 원본 읽기 | 사본 읽기 |
|---|---|---|
| B1F 현장조사 평면도 116 MB | 21.9초 | 약 10초 (훑기 0.9 · 사본 쓰기 포함 · 여러 번 재어 8.5~10.2) |
| MF-004 계통도 8.1 MB | 2.5초 | 1.4초 |
| 대명동 계통도 1.7 MB | 0.5초 | 그대로 (비울 것 없음) |

### ② 도면을 먼저 띄우고 ★추적은 이어서 (`api_slot._system_layers` · `static/module_f.js`)

- 레이어 표까지 만든 뒤 `sess["world"]` 를 앉힌다 → 화면이 «도면 준비됨»(`world_ready`)을 보고
  바로 그린다. ★추적 그래프는 그 뒤에 만든다.
- 그동안 표의 ★칸은 `mode: "pending"`(«고르는 중») — ★를 하나도 안 단다(자동 레이어에 잘못 달지
  않는다). 잡이 끝나 `/sub/graph` 가 ★를 주면 표를 다시 그린다(켜고 끈 상태는 그대로).
  ★를 못 고른 도면(null)은 종전처럼 자동 레이어 표시로 돌아간다.
- ★를 고르는 규칙과 결과는 그대로 — 순서만 바뀌었다.

### ③ 같은 도면은 기억한다 (`data/parse_cache/subview_*` · `subtrace_*`)

- 열쇠 = 파일 내용 지문(blake2b) + 코드 판번호(관련 소스 파일 · ezdxf · 파이썬 판의 지문).
  같은 내용이면 파일 이름이 달라도 같은 열쇠.
- 기억하는 것: 도형 목록(B1F 1.5 MB) · 레이어 표와 ★추적(2.2 MB). 금방 읽히는 도면(1.5초 미만) ·
  금방 고르는 ★(1초 미만)는 안 남긴다.
- 코드가 바뀌면 판번호가 달라져 기억을 안 쓰고 새로 읽는다. 판번호는 서버가 뜰 때 한 번 잰다
  (`api_slot` 이 시작 때 이 모듈을 부른다). 같은 도면의 옛 판 기억은 지우고, 종류마다 40개까지 둔다.
- 깨진 기억은 버리고 새로 읽는다. 끄는 스위치: `MODULE_F_SUB_CACHE=0`.

  서버(파이썬 3.13)는 중지 요청이 있을 때만 줄 감시를 켜므로 이 값과 같은 조건이다

# Module F 물흐름 정본 (2026-09-20)

## 사용자 계약

물흐름은 연결 확인 애니메이션이 아니라 **알람밸브에서 각 헤드까지 단 하나의 경로를 확정**하는 기능이다. 선을 직선으로 펴거나 원본 DXF/손질을 삭제하지 않는다. 최불리, 수리계산 및 전체망 변환은 그 경로를 읽는다.

1. 사용자가 선택한 알람밸브 하나를 뿌리로 정한다. 여러 밸브를 임의로 섞지 않는다.
2. 전체 손질 그래프에서 결정적인 최단경로 트리를 만든다. 비교 순서는 `(명시된 추정 연결 개수, 실제 길이 mm, 홉 수)`이며 동률은 노드 번호로 안정화한다. 추정 벌점은 실제 길이에 더하지 않는다. 현재 손질 데이터가 추정 연결 출처를 제공하지 않으면 추측해서 표시하지 않는다.
3. 같은 위치의 중복 헤드 표시는 기존 0.1mm 자리 규칙으로 묶는다. 전체 헤드의 담당 수를 트리 하류에서 상류로 합산한다. 사이클에는 하류 수가 유일하게 정의되지 않으므로 **트리 확정 후** 센다.
4. 전체 헤드로 가지 않는 가지와 비선정 대체 경로를 계산망에서 제외한다. 원본에는 남아 부속 종류 판정에 사용된다. 다른 연결 성분도 `unreachable`로 보존한다.
5. 영역/도면 장은 후보 헤드만 제한한다. K나 영역을 바꿔도 전체 경로 트리는 바뀌지 않는다. 그 경로 거리의 내림차순으로 K개를 골라 경로 합집합을 넘긴다. 연결 실패 헤드를 다른 헤드로 채우지 않는다.
6. 전개기는 이 간선과 헤드 참조만 사용한다. 격자 근접 병합, 티 겹침 재분할, 헤드 재접속으로 새 경로를 만들지 않는다. 이미 연결된 실제 길이 0의 중복 절점만 축약할 수 있다. 전개 후 단일 연결 성분이며 `배관 수 = 노드 수 - 1`인지 검사한다.
7. 부속의 포트는 **가지치기 전 원본 배관망**에서 읽는다. 선택망에서 팔이 사라져도 원본 티는 엘보로 낮추지 않는다. 합쳐진 배관의 중간 부속도 확정된 원본 경로에서 찾는다.
8. `worst.loads`는 선정 부하(표시용), `worst.physical_loads`는 전체 원본 트리 부하다. 전개 배관별 `physical_pipe_loads`가 관경 입력이다. 중간 구간을 합친 배관은 해당 원본 경로의 최대 부하를 유지한다. 추가된 상승관에는 하류 전체 부하를 전달하고, 헤드 접속관은 해당 헤드만 담당한다.
9. 평면 배관 계산 길이는 양끝 직선거리가 아니라 확정 경로의 실제 길이 합이다. 선언된 신축배관 길이도 mm→m으로 보존한다. Z/접속관은 기존 입력 규칙을 따른다. 화면용 8방향 배치는 계산 경로와 별개다.
10. 손질/급수원 변경은 표시를 무효화한다. 정확한 그래프 지문으로 캐시를 검증하고, 이전 물흐름에서 만든 표의 재사용/내보내기를 차단한다.

## 한계와 해석

이것은 사용자 PDF의 경로 정리 모델이다. 실제 환상배관에서 양방향으로 나뉘는 유량을 수리학적으로 푼 결과가 아니며, 실제 배관이 없어졌다는 뜻도 아니다. 최불리 순위는 경로 길이 대용 지표이며 최종 압력손실 최적화나 법규 적합 판정을 대신하지 않는다. 근접/교차 도형을 자동으로 실제 연결이라고 판단하지 않는다. 새 도면의 레이어·헤드 접속 정확성은 여전히 손질에서 확인해야 한다.

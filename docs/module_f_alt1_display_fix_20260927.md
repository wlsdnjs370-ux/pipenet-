# ALT-1 찍기 화면 누락 — 2026-09-27

## 원인과 원본 대조

대상: `data/uploads/B1F 현장조사 소화설비 평면도_컨셉2-수정본 (1).dxf`.

DXF 준비 단계는 선분 207,132개와 ALT-1 550개를 모두 읽었다. 그러나
`routes/module_f/world.py`가 전체 선분의 앞 150,000개만 화면에 보내면서
뒤쪽에 저장된 ALT-1 일부를 생략했다. 색상 3 묶음은 목록에서도 빠졌다.
이는 트리/루프 판단이나 DXF 레이어 필터의 오류가 아니라 표시 데이터 제한 문제다.

| --- | ---: | ---: | ---: |
| 1 | 285 | 100 | 285 |
| 5 | 210 | 75 | 210 |

## 변경

- 초기 표시 예산 150,000개는 유지한다. 레이어×색 묶음별 max-min 배분으로 작은 묶음부터 전량 보존한다.
- 큰 묶음의 표시용 표본은 처음/끝을 포함해 분산한다. 레이어 이름이나 도면명을 특수 취급하지 않는다.
- 표시하지 못한 묶음도 실제 개수와 함께 목록에 남긴다.
- 평면도 레이어 목록의 `일부 표시 · 전체 보기`로 해당 묶음의 모든 도형을 불러온다.
- 전체 보기는 현재 잘라낸 작업 도면에서 읽는다. 원본 DXF의 제외 영역을 다시 가져오지 않는다.
- 배관 재료 선택, 원본 world, 물흐름·루프 추출 데이터는 변경하지 않는다.
- 전체 보기 요청 중 다른 도면/슬롯으로 전환하거나 자르면 이전 응답을 버린다.

실도면 재측정: ALT-1 550개 모두 표시, 전체 최초 선분 표시 150,000개 유지,
일부 표시로 남은 묶음 2개. 펜 자르기 후 표시 예산 이내이면 전량 표시한다.

검증: `tests/test_module_f_world_display.py` — 저장 순서와 무관한 묶음 보존,
원·호 제한, 원본 불변, 실제 API 전체 보기, 잘라낸 영역 유지, 브라우저 버튼 동작.
기존 묶음 선택/확대, 도면 직렬화, 자르기, 트리·루프 변환 회귀검사도 실행한다.

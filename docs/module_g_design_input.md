# 모듈 G — 최불리 배관망 확정과 수리계산 입력(SDF) 생성

작업 대상 트리 `cad_project_editor_g/`. `cad_project_editor/`(모듈 E)와
`routes/module_f/` 는 읽기 전용 참조이며 한 줄도 고치지 않았다.

---

## 1. 이 작업이 무엇이었나

`.kfp` 는 K-Fire Solver 가 **전체망**을 받아 설계구역·최불리를 제 안에서 고른다.
`.sdf` 는 PIPENET 이 **주어진 망을 풀 뿐** 설계구역을 스스로 고르지 않는다.
그래서 이전의 SDF 는 「전체망을 PIPENET 문법으로 옮겨 적은 파일」이지 수리계산
입력이 아니었다. 이번 작업은 **최불리 확정 → 위상 정리 → 테이블 채우기**를
프로그램이 미리 하도록 만든 것이다.

### 두 번 전개

```
EditBoard ─┬─ 전체망 전개 ─────────────→ .kfp   (기존 경로 · 손대지 않았다)
           └─ 최불리 제한 → 제한 전개 → 5표 → .sdf   (이번에 신설)
```

같은 손질 결과·같은 치수 입력에서 두 산출이 나오므로 설계 내용이 어긋나지 않는다.
**전체망 `.kfp` 는 작업 전후로 비트 동일**하다(sha256 `c8dde8f4…` · 노드 1,445 ·
배관 1,444). 여덟 항목 내내 매번 확인했다.

## 2. 구성

```
services/cad_import/design/
  worst.py     [G1] 최불리 K 선정 (앵커 방식) · 도면 장 나누기
  restrict.py  [G2] corridor 제한 payload · 제한 전개 · 붙일 수 있는 헤드 판정
  bore.py      [G3] 관경 결정 (혼합 규칙)
  fitting.py   [G4] 부속 판정 · 등가길이 · 노즐 · 기기
  tables.py    [G5] 5개 테이블 조립 (PipeTablesG)
  emit.py      [G6] SDF + SLF 방출
ui/dialogs/dialog_design_input.py   [G7] 네 번째 창
tests/                              검증 · 회귀 기준선 · A 대조
```

`worst` · `restrict` · `bore` · `fitting` 은 모듈 A/F 에서 **로직 변경 없이**
옮겨 왔다. 실제로 새로 짠 것은 `tables.py`(G5)와 창(G7) 둘뿐이다.

## 3. 최불리 배관망을 어떻게 정하나

1. **앵커** = 급수원에서 배관 거리로 가장 먼 헤드. 여기가 기준압 지점이고,
   급수원↔앵커가 「최원 유하거리」다.
2. **설계면적** = 앵커에서 **배관 거리로** 가까운 K개. 유클리드가 아니라 배관
   거리라야 실제로 같은 관을 타고 함께 흐르는 무리가 된다.
3. **corridor** = 그 K개를 급수원까지 잇는 최단경로 합집합 + 간선별 **담당 헤드
   수(load)**. 최대 load 가 NFPC 별표1 의 주배관 관경을 정한다.

「먼 순서 K개」와의 차이는 실측이 그대로 보여준다 — B1F 에서 헤드 퍼짐
**134.1 m(먼 순서) 대 33.5 m(앵커)**. 흩어진 30개로는 설계면적이 성립하지 않는다.

## 4. 관경 · 부속

관경은 **혼합 규칙**이다.

```
nfpc_min = 별표1('가'칸)[담당 헤드 수]
text     = 선분에서 수직거리 ≤ 1500 mm 인 가장 가까운 치수 텍스트
dia = nfpc_min (텍스트 없음) | nfpc_min (텍스트<최소, 안전측) | text (그 외)
```

치수 텍스트는 **DXF 를 다시 읽지 않는다** — handoff 캐시의 `world.texts` 에 이미
있다. B1F 실측 3,168개 텍스트 중 관경으로 읽히는 것 533개.

부속 판정은 `core/fitting_rules.py` 를 그대로 부른다. **직진해 지나가는 갈래는
직류티라 계상하지 않는다**(마찰손실 비 10:1). 등가길이는
`fittings_library_v3.json`(NFPA13 2025)에서 가져오고, **없는 칸을 0 으로 채우지
않는다** — 0 은 「손실 없음」이라는 거짓말이다.

## 5. 알아야 할 함정

| | |
|---|---|
| **T1 좌표 추적** | 관경 매칭은 평면 mm, 테이블은 전개된 m. `edge_ref`(kfp 배관 → 원 board 간선)로 되짚는다. **노드정리가 배관을 병합하며 새 id 를 매기므로** 정리 직후 `node_ref` 로 역참조를 복구해야 한다(실측: 53개 중 36개가 비었다). |
| **T2 두 개의 답** | `.kfp` 는 솔버가, `.sdf` 는 G 가 최불리를 고른다. 두 결과가 다를 수 있고 **버그가 아니다**. 산출물 meta 와 창에 그렇게 적었다. |
| **T3 단위 혼재** | 노드 x/y 만 **mm**. elevation·length·elev 는 m, 압력은 Pa. |
| **T4 담당 헤드 수** | 별표1 입력은 corridor 안의 K개 기준. 전체망 하류 수를 넣으면 관경이 과대해진다. |
| **T5 템플릿 자산** | 없으면 관경이 "Unset" 이 된다. G 는 **경고가 아니라 실패**로 처리하고 파일을 만들지 않는다. |
| **T6 캐시 분리** | G 는 제 트리에서 작업 폴더를 잡는다. E 와 동시에 띄워도 안 섞인다. |

## 6. B1F 실측 산출

```
설계면적 30헤드 · 앵커 126.99 m · 폭 31.35 m
corridor 노드 54 / 배관 53 / 총연장 177.34 m · 주배관 담당 30
관경 [25 40 50 65 100 150]  근거 텍스트 17 · 별표1보강 4 · 별표1폴백 32
부속 엘보45 2 · 엘보90 5 · 분류티 10   판정불가 0 · 등가길이 미해결 0
SDF 25,503 B + SLF 8,412 B · 관경 Unset 0건 · Graphics 보존
```

**후보 619 / 도면 3,163 — 전개가 붙이지 못해 제외한 헤드 2,544개.**
이 수가 크다는 것은 그 도면의 배관이 끊겨 있다는 뜻이다. 창이 이 수를 띄우고,
절반을 넘으면 「손질 창에서 배관을 이어 주세요」까지 말한다. 조용히 빼면 더
불리한 헤드가 있는데 못 본 채 수리계산이 나간다. → `BLOCKED.md` B4.

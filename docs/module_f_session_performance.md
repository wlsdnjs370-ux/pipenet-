# Module F 세션 처리 속도 개선 — 2026-09-23

## 적용 범위

4단계를 작은 변경으로 순차 적용했다. 전 경로의 복사를 일괄 제거한 것은 아니다.
계산식, 관경 판정, 실좌표/표시좌표, 배관 길이와 표고, SDF 구조는 변경하지 않는다.

1. 측정: 세션 복사, 핸들러/JSON 응답 구성, 무거운 작업 대기/실행,
   확정 상태 반영, 편집 이력 재실행 시간을 기록한다.
2. 복사 범위 축소: 물흐름·최불리 선정은 해당 손질/선정 상태만,
   급수방식 변경은 방식·낙차·펌프 설정만 복사한다.
3. 확정 상태/작업판 분리: 위 세 경로는 별도 작업판에서 계산하고 성공해야 반영한다.
4. 편집 기록: 명령 JSON은 그대로 유지하고, 매 10건마다 그래프 중간 저장점을
   최대 2개만 메모리에 보관한다. 되돌리기는 가장 가까운 유효 저장점부터 재실행한다.

## 1. 측정

`routes/module_f/performance.py`에 최근 400개 이벤트를 프로세스 단위로 보관한다.
조회는 기존 인증 안에서 `GET /api/module-f/performance?sid=현재세션`을 사용한다.
해당 세션의 이벤트만 반환하며 도면 좌표, 텍스트, 파일 내용, 비밀번호는 기록하지 않는다.
새 파일을 계속 생성하지 않으며 운영 요청에서 메모리 전체 순회나 tracemalloc은 하지 않는다.

| 이벤트 | 측정 범위 |
| --- | --- |
| session_snapshot | 상태의 deepcopy |
| handler_and_json | 세션 확인 이후 핸들러 및 JSON 구성 |
| job_wait | 전역 작업 잠금 대기 |
| job_compute | 실제 작업 함수 실행 |
| session_publish | 작업판의 확정 상태 반영 |
| history_replay | 편집 명령 재실행; 전체 명령/재실행 명령 수 포함 |

브라우저 그리기·다운로드·네트워크 지연은 이 시간에 포함되지 않는다.
중첩된 이벤트를 합산해 전체 응답 시간으로 해석하면 안 된다.

## 2–3. 소유 범위와 안전장치

`session_policy.py`가 수정할 수 있는 최상위 필드를 명시한다. `None`은 기존 전체
백업 경로다. `session_workspace.py`는 그 필드만 깊게 복사하고 나머지는 읽기 전용으로
참조한다. 실제 수정 중에는 같은 세션을 향한 다른 쓰기를 409로 거절한다.

- 성공: 세션 버전·활성 슬롯·도면 키가 여전히 같으면 소유 필드만 확정한다.
- HTTP 오류, `ok=false`, 예외, 취소: 작업판을 폐기한다. 이전 확정판을 복원하는
  방식이 아니므로 다른 최신 상태를 오래된 사본으로 덮어쓰지 않는다.
- 계약에 없는 최상위 필드의 추가·교체·삭제는 반영을 거절한다.
- 작업판 처리 중 지연 캐시를 수정할 수 있는 일반 GET도 거절한다.
  작업 진행/취소/측정 조회는 계속 허용한다.
- 이미 진행 중인 동일 작업 ID의 중복 POST는 첫 작업에 영향을 주지 않고 거절한다.
- 세션 버전은 도면 슬롯 전환 때 슬롯 안으로 이동하지 않는다.

공유 객체의 **내부 중첩 변경**까지 자동 감시하는 범용 copy-on-write 구조는 아니다.
따라서 수정 범위를 실제로 검토한 경로만 허용한다. 새 경로를 추가할 때는 소유 필드,
호출 함수의 중첩 변경, 실패 응답, 취소, 저장 부작용을 함께 검증해야 한다.

파일 생성/저장 경로(표 확정·재추출·통합 산출·SDF 저장 등)는 기존 전체 백업을 유지한다.
파일 쓰기까지 원자적으로 확정하는 작업판으로 확장하려면 임시 파일 준비 → 버전 검사 →
파일 및 상태 확정 절차가 추가로 필요하다. 이번 작업에서는 중간 파일을 생성하는
비동기 작업이 제한된 작업판에서 시작되지 않도록 명시적으로 차단한다.
전역 무거운 작업 잠금도 공유 stdout/엔진 캐시 보호 때문에 유지한다.

## 4. 이력 경량화

`editor_history.py`의 캐시는 명령 앞부분의 해시와 기준 배관망/라이브러리 버전에 묶인다.
분기 편집으로 바뀐 명령, 표 재확정, 통합 재결합, 라이브러리 변경에 낡은 그래프를
사용하지 않는다. 초기화하면 비우며 파일을 다시 열면 명령을 재실행해 복구한다.

중간 저장점 그래프는 외부에 직접 노출하지 않는다. 반환 시 복사하고 캐시 갱신 시
새 캐시를 만든다. 따라서 세션 취소 백업에서 캐시 자체를 다시 깊게 복사하지 않아도 된다.
저장되는 JSON은 기존 version 1 명령 목록이며 그래프 저장점은 디스크에 쓰지 않는다.

최근 이력은 보통 1~10개 명령만 재실행하지만, 남아 있는 저장점보다 오래전으로
되돌리면 기준 그래프부터 재실행할 수 있다. 그래프 편집 1건 자체의 안전한 deepcopy와
검증은 유지한다. 저장점 2개의 상주 메모리 비용은 새로 생기므로 메모리 무비용 개선은 아니다.

## 재현 가능한 합성 벤치마크

`python scripts/benchmark_module_f_sessions.py --nodes 5000 --runs 3 --history-nodes 200 --edits 60`

서버·사용자 저장 파일은 건드리지 않는다. wall time과 tracemalloc은 별도 실행한다.
2026-09-23 로컬에서 3회 중앙값:

| 구간 | 기존 경로 | 개선 경로 |
| --- | ---: | ---: |
| 합성 5,000노드×여러 도면/결과 상태 복사 | 162.29 ms | 작업판 준비 13.37 ms |
| 복사 순간의 추가 할당 최대치 | 14.00 MiB | 0.08 MiB |
| 합성 200노드/60건 편집에서 59건 상태로 되돌리기 | 286.03 ms | 47.33 ms |

이 수치는 해당 부분의 미세 벤치마크다. 실제 B1F 전체 처리 시간의 배속으로 환산하지 않는다.
튜플/수치 등 불변 값이 많은 합성 선정 상태의 메모리 절감폭도 실제 도면과 다를 수 있다.
이력 벤치마크는 저장점을 미리 만든 뒤 재실행 비용을 비교하며 상주 캐시 메모리는 포함하지 않는다.

# Module H 측벽 헤드 인식·선택 수정

## 원인과 변경 범위

- MF20 원본의 `측벽(드라이펜던트)`는 `Sp-head`에 속하지만 -Z OCS INSERT의 좌표가 자동 후보 쪽에서는 음수 X로 남았다. 표시 엔진은 양수 X로 읽어 두 경로가 어긋났다. 자동 인식의 INSERT 원점 및 자식 변환을 ezdxf의 OCS/블록 변환으로 처리한다. 이전 파싱 캐시는 새 버전으로 분리한다.
- 기호 내부 원은 `CIRCLE`이 아닌 닫힌 2점 LWPOLYLINE이다. 두 bulge가 같은 방향의 반원(±1)인 실제 원만 후보 엔진에서 원으로 읽는다. 임의의 닫힌 2점 선, 열린 선, 비균일 확대된 타원은 원으로 승격하지 않는다. 레이어 매핑과 기존 0.75/0.90 임계는 그대로다.
- 작은 닫힌 삼각형은 기존 등변·크기 검사를 통과한 경우 내부도 클릭할 수 있다. 삼각형에 완전히 포함된 유일한 원이 있으면 테두리/내부 모두 그 원의 동일한 헤드 서명을 선택한다. 같은 헤드를 원과 삼각형 두 개로 세지 않는다. 알 수 없는 블록의 사각 경계만으로 헤드를 만들지 않는다.
- 배관/헤드 선택 도구가 성공적으로 켜지면 펜 자르기 모드를 해제한다. 그려 둔 경계와 기존 선택 기록은 지우지 않는다.

H가 공유하는 인식·선택 코드의 수정이다. 물흐름/트리·루프·그리드 연결, 관경 역산 및 SDF 계산값 생성 로직은 변경하지 않았다. 헤드 방향·K값·온도·관경을 이름만 보고 자동 확정하지 않는다. 범례·다른 레이어의 기호는 기존 분류/작업 영역 정책을 따른다.

## 실제 도면 대조

`python -X utf8 -m scripts.audit_h_sidewall_heads`

원본을 읽고 별도 메모리의 시험판에서 검사한다. 원본, 저장 스펙, 실행 중 세션을 변경하지 않는다. 결과는 `outputs/h_sidewall_head_review/report.json`.

- 같은 블록 참조 6개 중 HEAD 레이어 4개를 자동 후보·선택 모두 4개로 확인.
- `tx` 레이어의 나머지 2개는 헤드 계열로 무조건 승격하지 않음.
- 후보 신뢰도 0.85, 표시 엔진의 몸통 중심과 좌표 오차 0 mm.
- 반복 채택 후에도 4개 유지. 삼각형 밑변·삼각형 내부·내부 원 중심이 같은 선택 서명으로 등록됨.
- 516 MB 전체 원본을 새 파서로 읽어 후보 206개를 확인했다. 실제 채택 기준 0.75로 전체 선택을 시험해 실패 0건, 선택 원 194개(기존 화면 190개 + 해당 4개), 문제 위치 중복 0건을 확인했다. 준비된 도형에서 채택 처리 시간은 약 0.29초였다.

## 검증 및 한계

집중 시험은 `tests/test_module_h_sidewall_head_pick.py`, `tests/test_module_h_pick_tools_browser.py`. 일반·반전 INSERT, 중첩/회전/블록 기준점, 이름만 있는 미확인 블록, 잘못된 원 승격 방지, 수동 선택/되돌리기/반복 채택, 실제 브라우저의 펜→헤드 선택을 다룬다.

넓은 기존 회귀 검사에서 `test_module_f_adopt.py`의 4개 소스 문자열 검사(계통도 열기 호출문, 초기화 구간 길이, 안내 문구, 영역 복제 표현)와 `test_module_f_sub_fastread.py::test_unknown_or_odd_files_are_read_as_is`의 REGION 처리 기대값은 실패했다. 해당 조건의 구현은 이번에 수정하지 않았으며 전체 회귀 통과로 보고하지 않는다.

아직 임의 블록 전체를 의미적으로 해석하는 범용 객체 인식은 아니다. 기존 도형 검사에서 확인할 수 있는 원·작은 삼각형의 선택 영역을 개선했다. 비균일 확대와 임의 3D 투영은 별도 검토 대상이다.

## 적용

5051 서버 재시작 후 도면을 다시 연다. 기존 저장본을 복원한 경우 과거의 헤드 선택 결과가 그대로 복원될 수 있으므로 객체 정의에서 자동 인식 재적용 또는 헤드 직접 선택을 실행한다. 새 인식 결과가 기존 계산망을 조용히 덮어쓰지는 않는다.

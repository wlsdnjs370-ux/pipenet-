## 권장 조치와 적용 조건

### 1. 근본 수정: 축 연장 시 기준 노드의 다른 두 좌표 보존

편집기에서 길이 입력만 스냅하고, 종점은 기준 좌표에 해당 축의 길이를
더해 만든다. 노드 생성 단계에서도 다른 두 좌표가 재스냅되지 않도록
명시적인 좌표 보존 경로가 필요하다. 첫 번째 `snap_point`만 없애면
`NodeManager.add_node`의 두 번째 스냅이 남으므로 불충분하다.

이 수정은 설치된 Solver 쪽에 적용돼야 한다. 저장소의 모듈 G 편집기를
고치는 것만으로 이미 설치된 Solver 실행 파일이 바뀌지는 않는다.

### 2. 모듈 F에서 할 수 있는 대응

- 출력 직전 축 평행성과 편집 격자 적합성을 따로 검사한다.
  기존 배관이 사선인 경우와, 정상 배관의 기준 좌표만 격자 밖인 경우를 구분한다.
- 원본 좌표 보존을 기본으로 삼는다. Solver의 실제 버전에서 지원·저장되는
  격자 설정을 확인한 뒤 호환 설정을 출력에 포함한다.
- `grid_step=1e-6`만 추가하는 방식은 현재 저장소 엔진에서는 첫 편집의
  오류를 없애지만 저장·재열기까지 보장하지 못하므로 완전한 수정으로 배포하지 않는다.
  격자를 세밀하게 바꾸면 기존 노드에 붙는 스냅 허용범위도 달라지므로 함께 검증한다.
- Solver 수정이 불가능해 0.01m 격자 파일이 꼭 필요하다면, 별도 편집용
  출력으로 제공하고 변경된 좌표·길이를 보고한다. 짧은 배관 소실, 노드 겹침,
  실제 대각 배관 변형을 검사하고 계산용 원본을 조용히 덮어쓰지 않는다.

### 수용 기준

1. 양수·음수의 격자 밖 기준점에서 ±X/±Y/±Z 배관 추가가 축 조건을 유지한다.
2. 기존 배관과 겹치는 방향은 여전히 거부되고, 교차점 연결·배관 분할이 유지된다.
3. 추가하기 전 기존 노드 좌표, 배관 연결·길이·관경·등가길이가 바뀌지 않는다.
4. 실제 Solver에서 저장 후 새로 열어도 같은 편집이 가능하다.
5. 생성 실패 시 임시 노드나 배관이 남지 않는다.

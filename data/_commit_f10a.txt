[F-10a] 방식 질문 제거 — 기본 흐름 자동화 · 수용기준: PASS

2026-08-27 상무 시연에서 세 차선을 설명했고(전사 12:07 · 16:03), 그 뒤에도 28분
내내 **단 하나의 흐름**만 다섯 번 반복해서 요구했다(06:48 · 07:44 · 17:15 ·
22:54 · 25:38). 사용자 머릿속에 «차선» 이라는 개념이 없다. 그리고 업로드 시점에는
이 도면이 자동으로 될지 사람도 모르므로 「어떻게 추출할까요」는 **답할 수 없는
질문**이었다.

없앤 것은 질문 하나(`panel-method`)다. 엔진 두 경로는 그대로 산다 — A 의 자동
추출과 E 의 물길 판정은 「이어져 있다」의 정의가 달라, 그래프를 섞으면 G-BLOCKED
B4 실측(헤드 물닿음 0 · 노드 2)이 재현된다(§0.2 · §3).

■ 바뀐 흐름 (D-F10-1 · 2 · 3)

    업로드 → 열기+정찰(F-8a 그대로)
      → 정찰 성함: 채택(기본 0.9) → 조립 → 손질 진입 · 배너
      → 못 씀     : 찍기 진입 · 배너에 사유       ← 묻지 않는다

  · `panel-method` 와 그 JS 분기 제거. 「고르기 전에는 읽기를 시작할 수도 없다」던
    옛 주석도 걷었다 — 읽기·정찰이 방식보다 먼저 돈 지 오래다.
  · 자동 차선 입구는 «고급» 접힘 안 한 줄로(D-F10-2). 채택 기준(0.9)은 질문이
    아니라 «설정» 으로 옮겼다 — 기본값은 D-F8-4 그대로다.
  · 슬롯을 오갔다 돌아오는 길도 같은 판단을 탄다(예전엔 여기서 다시 물었다).

■ 조사가 잡은 것 — 채택 헤드 0 이면 조립이 죽는다

브라우저 검증이 「배관망 구성」 잡의 error 를 잡았다. 서버에서 재현해 원인을
글자 그대로 확인했다: 높음 띠가 0 인 도면(LH306 0/42)은 0.9 로 헤드가 0 개
찍히고, 그 스펙으로 조립하면 엔진이 `KeyError: 'heads'` 로 죽는다(0.75 면 정상).
엔진은 이번 지시서에서 읽기 전용이므로 **F 의 문 앞에서** 막았다.

기준을 프로그램이 자동으로 낮추지 **않는다** — 그러면 사람이 모르는 사이에 낮은
신뢰도 후보가 산출에 들어간다. D-F8-4 는 「기본 0.9」만 정했지 «0 일 때» 는 안
정했으므로 BLOCKED §16 에 질문으로 남기고, 임시 우회(고급에서 0.75 로 다시
채택)를 붙였다.
